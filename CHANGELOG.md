# Changelog

All notable changes to Rivelle will be documented here. The project follows Semantic Versioning once the public package is released.

## [Unreleased]

## [0.5.0] - 2026-07-18

### Added

- Tag Input with keyboard creation, paste parsing, validation, limits and form-friendly values.
- Multi Select with search, disabled options, selection limits, select-all and compact value summaries.
- Six reusable site compositions: responsive header, profile card, feature section, testimonial section, contact form and footer.
- A dedicated Templates registry and documentation section with complete SaaS Landing and Creative Portfolio interfaces.

### Changed

- Replaced the ambiguous Examples destination with installable, responsive Templates across navigation, search, sitemap and project documentation.
- Extended CLI routing and registry verification for complete `registry:page` templates in TypeScript and JavaScript projects.
- Made contact forms and footers configurable enough to support product and portfolio layouts from the same reusable source.

### Fixed

- Constrained the standalone Profile Card width while preserving layout overrides and responsive template placement.
- Prevented template detail pages from overflowing on narrow screens.
- Raised Sheet overlays above sticky documentation navigation and generated unique form control IDs across multiple previews.

## [0.4.0] - 2026-07-17

### Added

- Rivelle Effects, a separate collection for expressive interactive elements that complements the foundational UI catalog.
- Eleven deliberately distinct effects: Compare Slider, Direction Reveal, Cursor Lens, Draggable Stack, Cursor Gradient, Ripple Grid, Tilt Card, Perspective Grid, Text Scramble, Magnetic Button and Shimmer Button.
- Category filters for Effects and Blocks, keeping motion primitives separate from assembled interface compositions.
- Dedicated `/effects` gallery and per-effect documentation with Nova and Prism previews.
- CLI routing for effect source files under `components/effects` while preserving the existing `rivelle add <name>` workflow.

### Changed

- Project metadata, navigation, search and the homepage now surface components, effects and blocks as distinct collections.

### Fixed

- `rivelle --version` now reads from the package manifest instead of a stale hardcoded value.
- The selected font now overrides unlayered starter-template `body` declarations such as the Arial stack generated by Next.js.

## [0.3.0] - 2026-07-16

### Fixed

- `add` now repairs missing font and motion dependencies when installation was skipped during `init`.
- Skipped theme installation now prints the exact package-manager command required to finish setup.

### Added

- Nova and Prism component style presets selectable during `rivelle init`.
- Shared action, control and surface recipes that carry the selected style across the registry without expanding component variant APIs.
- Nova and Prism preview controls across every component page, block detail and the blocks gallery.
- A contained Navigation Menu documentation preview that reserves space for its animated viewport.
- Working GitHub and npm links, documentation search, copy-page behavior and refreshed site copy across the home, docs and blocks routes.
- Initial Rivelle CLI, theme engine and shadcn-compatible source registry.
- 53 editable React and Next.js components.
- Alert Dialog, Button Group, Input Group, Field, Table, Pagination, Empty and Spinner primitives.
- Form, Combobox, Calendar, Date Picker, Drawer, Navigation Menu and Input OTP primitives.
- Carousel, Resizable, Menubar, Kbd and Item primitives.
- Login, Sign Up, Hero, Pricing, Sidebar, Dashboard Shell, Settings and Empty Project blocks.
- Dedicated `/blocks` gallery with full-size previews and install commands.
- Prism variants for Button and Input, inspired by high-contrast financial product interfaces.
- Interactive documentation, theme studio and syntax-highlighted usage examples.
- TypeScript and JavaScript HTTP installation verification.

### Changed

- CLI `0.2.0` installs `registry:block` files into `components/blocks` while keeping primitives in `components/ui`.
