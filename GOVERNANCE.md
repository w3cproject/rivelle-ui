# Governance

Rivelle currently uses a maintainer-led model.

Maintainers set project direction, review contributions, manage releases and enforce community policies. Decisions prioritize accessibility, editable source ownership, stable public APIs and a coherent design language.

Substantial changes to architecture, tokens, CLI behavior or public component APIs should begin as a GitHub Discussion or proposal issue before implementation. Routine fixes and documentation improvements can go directly to a pull request.

As the contributor community grows, trusted recurring contributors may be invited to triage, review or maintain defined areas of the project.
